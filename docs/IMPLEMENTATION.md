## 当前是否需要 LangChain / LangGraph / 向量数据库

当前不需要：本地命令是有界规则解析，E0分析是只读工具加模板，Demo是合成预设。终端更新另加可选的服务端OpenAI Responses适配和小规模本地词法向量检索，均未依赖这些框架。交易检索、金额汇总、版本和确认均由现有SQLite/业务程序处理。接入大模型也不强制依赖这三者，可先使用模型SDK与受限工具适配层。

| 组件 | 何时重新评估 |
|---|---|
| [LangChain](https://docs.langchain.com/oss/python/langchain/overview) | 需要统一多模型、工具及中间件接口时，作为可选集成层 |
| [LangGraph](https://docs.langchain.com/oss/python/langgraph/overview) | 多步骤任务需要持久状态、中断恢复、人工审阅和复杂分支时，作为可选编排层 |
| [向量检索](https://docs.langchain.com/oss/python/langchain/retrieval) | 大量非结构化文档需要按语义检索与引用回答时；金额与账本事实仍由SQL/精确计算产生 |

若产品目标改为自由多轮理解，下一步应先增加独立LLM适配与评测，保留现有确认、权限、版本和金额校验。未来的向量索引、对话检查点及缓存都属于新增数据副本，必须纳入用途授权、保留、导出和删除；不能因为引入框架而扩大财务写入权限。以上是后续选择条件，本轮未安装这些依赖。

按用户提供的六张参考图实现深色终端界面：资产/收支图、全局模块检索与悬浮任务助手、凭证来源和文字框定位、账本筛选排序/选中CSV、配置权重工作表、单序列历史单位价格风险实验、蒙特卡洛规划、安全页和Settings。原有月报保持真实PDF，正式与Demo共用界面并保留各自数据边界。规划和风险是明确标记的统计示意，不写实际账本、不交易、不使用虚构历史填空。

新增可选OpenAI解释是独立的只读入口：环境密钥、固定TLS目标、逐次完整payload预览、两分钟会话/版本绑定的一次性确认；默认没有云请求。E0四工具、本地规则与原nonce/Decimal事务不改。资料库按分析用途授权，TXT/MD/文本PDF在本机分块检索；使用384维哈希词法向量，不宣称神经语义检索。不需要LangChain/LangGraph/外部向量数据库。

下载备份可用WebCrypto AES-GCM加密并在页面验证口令和文件完整性，工作SQLite仍明文。加密备份验证不等于完整恢复验收。源PDF留在浏览器内存，正式单页扫描件转本地OCR；多页文本PDF最多5页/20,000字符，扫描多页需要拆分。资料/配置进入现有settings JSON，导出/删除覆盖；锁定和删除也清理未发送的云端payload。无新数据库表或schema迁移。

代码与数据口径决策见[ADR 003](adr/003-terminal-reference-workspace.md)，最新实际验证见[UX_VALIDATION](UX_VALIDATION.md)。上表和UX 1.0正文描述原基线；本节覆盖新增功能。实时行情、银行/税务/交易连接器、托管租户隔离及数据库静态加密仍未实现，不以参考图中的状态文字替代真实能力。
