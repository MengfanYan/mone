# 账单确认后的页面滚动修复

日期：2026-10-17（Australia/Sydney）。

## 根因与修改

编辑抽屉切换到确认弹窗时，两个 `useModal` 实例分别保存和恢复
`document.body.style.overflow`。确认框保存的是抽屉留下的 `hidden`；
抽屉先关闭会使仍打开的确认框失去背景滚动锁，确认框随后关闭则恢复过期的 `hidden`，
导致页面无法纵向滚动。

在修改前的生产构建上，新增回归用例捕获了两项失败：确认框打开时计算样式为 `visible`，
所有弹窗关闭后计算样式却是 `hidden`。

修复移除各实例的内联 overflow 快照，改用 `body:has(dialog[open])` 根据实际 DOM 状态锁定。
最后一个弹窗关闭或卸载后，浏览器自动恢复正常样式，不依赖关闭顺序。
保留原生 `showModal()`、焦点循环与恢复、Esc、关闭按钮和背景点击行为。

## 回归范围

`tests/e2e/review-flow.mjs` 为正式本地版和 Demo 共用的回归流程：

- 账本更正编辑器 → 确认框切换期间，背景保持锁定。
- 取消、确认和 Esc 三种退出路径，重复打开/关闭。
- 所有弹窗关闭后，实际滚轮可以向下和向上滚动页面。
- 普通草稿确认（含重复交易复核）也验证滚动恢复。

测试使用临时合成账本，覆盖桌面和手机尺寸的 Chromium；不代表真实 iOS Safari 验收。

## 使用

已打开的旧页面需要完整刷新一次，以清除旧代码留下的内联 `overflow: hidden`。
开发模式刷新即可加载当前代码；若使用 `npm run demo:start` / `npm start`，需停止旧服务、
重新构建并启动后再刷新。该修复无需清除客户数据或重置 Demo。
