# ADR 003 · Six-reference terminal workspace

Date: 2026-10-15. Scope: the user's six supplied UI references and missing usable local interactions. The reference images are visual requirements, not authority to make external trades, invent live integrations, or claim database encryption.

Use one shared Next/React terminal UI for live and Demo, with the existing separate transports and storage. Keep all eight modules, English default/Chinese switching, fixed PDF statement snapshots, exact ledger arithmetic, immutable corrections and confirmation boundaries. The new navy/emerald/blue/violet skin uses responsive grids and a single floating task Agent popup. Global module search is keyboard accessible. Screen privacy removes financial views; it is neither authentication nor encryption.

Dashboard assets use confirmed cash and the latest recorded positive investment values in a single currency, excluding liabilities and missing assets. Monthly income/expenses remain period scoped. Curves use recorded weekly facts; SVG coordinates may use floating point, while displayed source amounts and allocation worksheets use exact minor units. User-defined allocation weights must total exactly 100%; remainder allocation conserves the total. CSV downloads are worksheets/records, never broker orders, and escape formula-leading text.

The separate planning engine is a seeded monthly lognormal illustration, 600–2400 paths in the UI, adjustable return/inflation/volatility/capital/contribution/age/goal assumptions, common random paths, percentile bands and model success rates. Contributions are constant in today's purchasing power. No taxes, fees, withdrawals, guaranteed performance or inferred market expectations. It never writes ledger or approved budget values. The single-price-series risk lab requires 21–500 regularly spaced dated positive unit prices and reports empirical loss percentile and observed-interval volatility. It is not whole-portfolio VaR and never substitutes holding-value changes for price returns. Working scenarios/price histories remain view-memory only.

PDF evidence stays in browser memory: at most 5 MiB, five text pages/20,000 extracted characters, or one scanned page rendered to a bounded local PNG. Text/scans use the existing separately consented evidence and reviewed confirmation flow; multi-page scans need splitting. The side-by-side workbench links detected word regions to field text. The colored match is navigational guidance, not calibrated accuracy. Text-library PDFs support up to 20 pages/50,000 characters. Original PDFs are not stored or uploaded; extracted evidence/library text is retained under the existing deletion lifecycle.

Settings are a new `terminal` JSON record in the existing private settings table; no schema migration or new dependency. Local TXT/MD/text-PDF documents are capped at 20 × 50,000 characters, chunked into 1,000-character spans with 150-character overlap, and searched with 384-dimensional hashed lexical cosine vectors, configurable top-K/threshold. These are lexical vectors, not neural embeddings. Derive vectors locally, keep source attribution, and include source/configuration records in full export/delete. Import/search require analysis consent; source deletion remains available after revocation. This corpus does not justify LangChain, LangGraph or an external vector database.

An optional **separate** OpenAI Responses explanation adapter accepts a server-only `OPENAI_API_KEY`; local commands and E0 do not use it. The destination is fixed, public DNS checked/pinned, TLS verified, no redirects, bounded timeout/response/output. No arbitrary provider URL, browser key input or automatic request. First show the exact question/excerpts/instructions/model payload and destination. A two-minute one-use challenge binds that payload, session and resource version; then require explicit confirmation. `store:false` is not a zero-retention promise. No ledger attachment, model tools, financial writes or trading authority. Untrusted source text is data, never executable instructions. Slow provider calls run outside the mutation lock; completion rechecks authentication, consent and data version, so lock/revocation/delete remain responsive and invalidated private results are discarded. Started transmissions cannot be recalled. Lock/delete clear pending in-memory payloads; environment keys stay outside ledger deletion. Provider protocol: [official Responses guide](https://developers.openai.com/api/docs/guides/migrate-to-responses).

Backup downloads optionally use browser WebCrypto AES-256-GCM, random salt/IV, PBKDF2-SHA256 600,000 iterations, authenticated metadata and a user-held 12–200-character password. Full export retains live reauthentication and confirmation; plaintext export data is encrypted only in browser memory. Cap plaintext at 32 MiB and reject unsupported/oversized envelopes. Local verification authenticates/decrypts in memory and does not restore data. Password recovery, database-at-rest encryption, complete recovery lifecycle and zero-knowledge service claims are out of scope. Working SQLite/Demo storage and ordinary PDF/CSV/JSON downloads remain plaintext.

Audit display verifies the current SHA256 chain and shows failure explicitly; it is not external attestation and cannot detect an entirely rewritten valid chain. Capability cards report actual scoped access, never a fabricated connected provider. Demo model output is a labeled hand-written preset, optional synthetic risk observations are explicit, and all operations remain offline.

Tests use independent temporary synthetic stores and deterministic samples. No personal SQLite database, real key, paid model request, bank connection or trade was used. Cloud transport is mocked and private-DNS rejection tested; real provider availability is not verified without a key. Browser coverage/remaining limits are recorded in [UX validation](../UX_VALIDATION.md).

2026-10-15 interaction correction: Agent starts minimized and owns the shared command composer on every module. Explicitly confirmed writes refresh and navigate to the affected data; read-only analysis replies appear in the popup and the Analysis page. Live projections have no financial defaults and are returned only by the consent-gated local simulation API. Demo remains an independent browser transport with illustrative assumptions.
